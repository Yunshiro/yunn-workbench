1. 概述与实施原则

当前研究任务使用 SessionManager.inMemory()，首轮输出完成后立即销毁 Session；前端只能停止或重新发起任务。下一阶段将研究任务升级为有生命周期的 Pi Session，并新增本地创作者画像和可审核的长期记忆。

推荐顺序：先建立画像与记忆的数据基础，再改造持续会话。这样首次创建持久化 Session 时即可注入稳定、可追踪的创作者上下文，避免后续重复迁移。

产品原则

  • 用户始终知道 Agent 记住了什么。
  • 用户可以编辑、停用或删除任何长期记忆。
  • 纠偏消息不丢失，并明确显示排队、已送达或失败。
  • 行动轨迹只展示工具与结果摘要，不展示隐藏思维链。

工程原则

  • SQLite 是业务状态的唯一事实来源。
  • Pi JSONL Session 保存模型上下文，数据库保存可查询的产品记录。
  • 所有 schema 变更采用向前兼容迁移。
  • 保留现有一次性摘要、评估、聚类流程。

2. 目标与非目标

本期目标

  • 研究运行中支持“立即纠偏”和“本轮结束后继续”两种输入。
  • 研究完成后可继续追问，不必丢弃工具上下文或重新读取全部素材。
  • 服务重启后可以恢复研究会话并查看完整消息、轨迹和候选版本。
  • 提供单一创作者画像，覆盖领域、受众、目标、表达风格、禁区和输出偏好。
  • 保存经过用户确认的长期记忆；支持查看、编辑、停用和删除。
  • 每轮候选选题形成版本，确认写入时明确关联版本。

本期非目标

  • 不接入互联网搜索、向量数据库或多用户账户系统。
  • 不让模型在未经确认时自动形成永久记忆。
  • 不实现多个研究任务并行运行；继续沿用单队列执行策略。
  • 不扩展到自动写文章、发布内容或桌面应用打包。

Session 生命周期

  1. 启动研究时用 SessionManager.create(cwd, PI_SESSIONS_DIR) 创建持久化会话，将 Session 文件路径和 ID 写入任务。
  2. 任务运行期间把 AgentSession 保存在活动注册表；HTTP 请求可调用 session.steer() 或 session.followUp()。
  3. 一轮结束后任务进入 awaiting_feedback，Session 保留短期缓存；超时后释放内存，但不删除 JSONL。
  4. 后续追问时用 SessionManager.open() 恢复上下文，再发送新的用户消息。
  5. 用户点击“结束研究”后进入 completed；候选仍可查看和确认，但不能继续写入该 Session。

4. 创作者画像与长期记忆

数据模型

表关键字段说明
creator_profiles id, name, domains, audience, goals, tone, avoid_topics, output_preferences, version, timestamps MVP 使用固定 ID default；数组和结构化偏好存 JSON。
memory_facts id, category, content, status, source_type, source_id, confidence, timestamps 状态为 candidate、active、disabled；只有 active 注入上下文。
task_profile_snapshots task_id, profile_version, snapshot, created_at 记录研究启动时使用的画像，确保任务可复现。

画像设置界面

在现有“Agent 设置”中增加“创作者画像”页签，采用短字段和标签输入，不直接让用户编辑整段 Prompt。

  • 身份：称呼、主要创作领域、常用平台。
  • 受众：目标读者、知识水平、关注问题。
  • 目标：增长、专业影响力、产品转化或知识沉淀。
  • 表达：语气、篇幅、语言、偏好的内容结构。
  • 边界：不做的主题、不接受的表达方式、必须遵守的事实要求。

记忆形成机制

  1. 首版只从明确行为生成候选记忆，例如用户确认某类选题、连续拒绝某种形式，或主动输入“记住……”指令。
  2. 候选记忆进入“待确认”列表，不立即影响后续研究。
  3. 用户确认后转为 active；编辑会创建更新时间并保留来源。
  4. Prompt 只注入画像摘要和最多 20 条相关 active 记忆，按类别、最近使用时间和置信度排序。
隐私边界：画像和记忆仅保存在 WORKBENCH_HOME。界面必须提供“导出画像”“清空长期记忆”以及单条删除功能；删除后不再注入任何新 Session。

5. 持续对话与任务纠偏

消息与候选版本

表／字段用途
research_messages记录用户和 Agent 的可见消息；字段包括 role、mode、content、status、created_at、delivered_at。
research_revisions每次 Agent 返回合法候选 JSON 后保存一个不可变版本，包含 revision、topics、strategy 和 created_at。
tasks.session_id / session_path关联可恢复的 Pi JSONL Session。
tasks.status增加 awaiting_feedback 和 completed，区分“本轮结束”和“研究正式结束”。

两种纠偏方式

立即纠偏（steer）

用于方向明显错误或需要立刻改变检索重点。运行中调用 session.steer(content)，消息在下一次安全边界进入上下文。

示例：“不要讨论写作效率，重点研究个人知识库的复利价值。”

本轮后继续（followUp）

用于补充要求而不打断当前工具链。运行中调用 session.followUp(content)；空闲状态下直接触发下一轮。

示例：“完成后再给我一个面向独立开发者的版本。”

API 设计

GET  /api/creator-profile

前端交互

  • 研究工作台中栏合并展示工具动作和用户消息，按时间排序。
  • 底部增加常驻输入框；发送按钮旁提供“立即纠偏 / 本轮后继续”选择。
  • 消息显示排队、已送达、处理失败状态；失败消息允许重试。
  • 候选区顶部增加版本选择器，默认展示最新版本，旧版本只读。
  • “停止”仍用于中止当前运行；新增“结束研究”用于关闭整个会话。
  • 重新打开历史任务时恢复消息、轨迹、当前候选版本和 Session 状态。

SSE 事件

新增 research_message、research_revision、research_queue 和 profile_memory_candidate。断线重连后仍以 REST 获取完整状态，SSE 只负责增量刷新。

6. 实施阶段与里程碑

阶段预计主要工作完成标准
P0 数据基础 1 天 新增表与字段、迁移函数、DB 类型、配置路径；为 Session 和业务消息建立关联。 旧数据库启动无损；新表可 CRUD；旧任务仍能读取。
P1 创作者画像 2 天 画像 API、设置界面、Prompt 摘要生成、任务画像快照。 新研究明确显示所用画像版本；编辑画像只影响新任务。
P2 长期记忆 1–2 天 记忆 CRUD、候选确认、禁用/删除、上下文筛选与注入。 未经确认的记忆不影响输出；删除后新 Session 不再出现。
P3 持久化会话 2 天 ResearchSessionController、SessionManager.create/open、状态机、候选版本。 首轮完成后可续问；重启服务后可恢复同一上下文。
P4 实时纠偏 UI 1–2 天 消息输入、steer/followUp、队列状态、时间线合并、版本选择。 运行中两种发送方式均可见、可追踪且不丢消息。
P5 稳定性与收尾 1 天 异常恢复、限制、导出/清空、手工回归和文档更新。 全部验收场景通过；失败不会损坏任务或画像数据。

8. 风险、回滚与待决策项

风险影响缓解措施
长会话导致上下文和成本持续增长延迟增加、超出模型限制启用 Pi compaction；界面显示轮次与用量；设置单任务最大轮次。
steer 与工具结束事件竞态消息状态错误或重复投递消息使用数据库 ID 和状态机；控制器串行更新；发送接口幂等。
模型学习出错误偏好长期污染后续结果只生成候选记忆，必须人工确认；支持停用和删除。
SQLite 与 Pi JSONL 状态不一致任务无法继续以 SQLite 记录 Session path 和最后确认轮次；打开失败时保留历史并提供“从快照新建会话”。
Prompt 注入内容过多稀释当前任务目标画像生成短摘要；长期记忆限制数量和总字符数。

回滚策略

  • 新表和新增列不删除旧数据；关闭功能开关后仍可使用当前一次性研究流程。
  • Session 恢复失败只影响继续对话，不影响已保存的任务输出和选题。
  • 画像注入保留总开关；异常时可立即停止注入而无需删除用户数据。

实施前需要确认的产品决策

  1. 记忆确认入口：推荐在 Agent 设置中集中审核，同时在研究完成后显示待确认提示。
  2. 画像生效规则：推荐任务启动时冻结快照；修改画像不改变正在运行的任务。
  3. 会话结束规则：推荐显式“结束研究”，另加 30 分钟内存缓存；磁盘 Session 长期保留。
  4. 首版限制：推荐单任务最多 12 轮、单条纠偏 2,000 字、活动记忆最多注入 20 条。

# 画板

画板把散落在 X 和网页上的素材收成一面可以拖动的墙。粘贴链接后，本机会去抓取内容并生成卡片；抓不到时可以自己贴正文。墙的右侧可以对着这些卡片多轮提问，回答会标出用了哪几张。

## 需求

1. 侧边栏有单独的「画板」入口，可以新建、重命名、删除多块画板。删除前要确认。
2. 粘贴或手动添加 X（`x.com` / `twitter.com`）、普通网页和 YouTube 链接，生成卡片。同一块画板上的同一条链接不重复添加。
3. 抓取失败或超过 15 秒时，卡片显示「抓取失败」，可以重试，也可以手动粘贴正文。任意卡片的正文都可以再改。
4. 卡片可以拖动、删除、打开完整正文，并在新标签页打开原文。画板可以缩放和平移。
5. 可以新建纯文本便签。便签和链接卡片一样能拖动、编辑、删除，也能被对话引用。
6. 右侧对话复用知识库已经在用的模型配置、Pi 多轮会话、SQLite 消息和引用展示。默认读取当前画板上的全部卡片；选中若干张时只读那几张。引用可以在画板上定位。卡片放不进上下文时明确提示，不截断。

## 非目标

- 不抓 Threads、小红书、公众号。
- 不做视频转录、自动打标签、爆款库搜索、排期或发布。
- 不做多人协作和画板分享。
- 不在浏览器里直接请求 FxTwitter 或其他第三方。

## 使用流程

1. 在 **Agent 设置** 里启用一个模型。画板对话和知识库用的是同一套配置。
2. 打开 **画板**，新建一面墙。
3. 在画布上按 `Ctrl/Cmd+V` 粘贴链接，或点 **添加链接**。几秒后卡片补全作者、正文或标题、摘要、封面。连续粘贴时，新卡片从当前视野中心往右、再往下排开，不会叠在同一点。
4. 双击空白处，便签出现在光标处。点 **新建便签**，便签出现在当前视野中心。
5. 把同一主题的卡片拖到一起。滚轮缩放，拖动空白处平移。
6. 在右侧提问。按住 Shift 再点卡片，可以让 AI 只看选中的几张。回答下方的「引用的卡片」会把对应卡片移到视野中间并高亮。
7. 如果某条链接抓取失败，点 **重试** 或 **手动粘贴正文**。保存后的正文和自动抓到的正文一样，重启后还在，对话也能读到。

普通文字粘贴不会生成链接卡片，也不会弹出错误。

## 设计

```text
画板页面（React Flow）
  -> /api/boards
  -> SQLite（画板、卡片、会话、消息）
  -> 服务端抓取
       ├─ X：api.fxtwitter.com
       ├─ YouTube：oEmbed
       └─ 网页：Open Graph / 标题 / 正文前一段
  -> 当前模型（与知识库相同的 Pi 会话）
  -> 回答 + 卡片引用
```

画布使用 `@xyflow/react`（MIT）。一百张卡片量级由它负责平移、缩放和拖动，页面只在松手时把坐标写回数据库。

### 链接

| 链接 | 识别 | 抓取 |
| --- | --- | --- |
| `x.com`、`twitter.com`、`mobile.twitter.com` 的状态页 | 同一条帖子的数字 ID | `https://api.fxtwitter.com/<user>/status/<id>`。封面优先用照片；纯视频帖用 `media.videos[].thumbnail_url` |
| `youtube.com/watch`、`youtu.be`、Shorts、embed | 视频 ID | YouTube oEmbed。失败时再试一次页面的 Open Graph |
| 其他 `http` / `https` | 去掉 hash 和末尾斜杠后的地址 | 标题、`og:description`（没有则取正文前一段）、`og:image`、站点名 |

抓取超时是 15 秒，响应体最多读 1.5MB。X 抓取失败只让这张卡片进入失败状态，不影响便签、网页卡片和画板本身。FxTwitter 不可用时同样如此。

单张网页正文在入库时最多保留约 8000 字，这是抓取上限。对话组上下文时不再截断：全部卡片的正文会原样放进提示词；估算 token 超过模型上下文扣除预留后的预算时，接口返回「卡片内容超出模型上下文，请选中部分卡片后再提问」。

### 对话

实现方式和知识库问答对齐：

- 是否已配置模型，走 `getAgentAuthConfig` / `prepareActiveModel`。未配置时返回「请先在 Agent 设置中启用一个可用的模型」。
- 多轮上下文放在 `board-sessions/` 的 Pi 会话文件里，工作目录是数据目录下的空文件夹，并关闭全部工具。
- 消息存在 `board_sessions` 和 `board_messages`。
- 模型用 `[1]` 这样的编号引用卡片。回答里出现编号时，只保留被点名的卡片；没有编号时，列出这次放进提示词的全部卡片。展示组件和知识库的引用来源是同一套样式。
- 实时更新走 SSE 的 `board_message` 和 `board_message_delta`。

选中卡片时，请求体带上 `cardIds`。没选时读取当前画板上所有已经有正文的卡片，不包括仍在加载、以及失败且还没粘贴正文的卡片。

### 数据表

`boards`、`board_cards`、`board_sessions`、`board_messages`。

这些表在启动时用 `CREATE TABLE IF NOT EXISTS` 补齐，旧的 `~/.workbench/workbench.db` 不需要手工迁移。画板记录不会随 RSS 保留策略删除。同一画板上的链接用 `dedupe_key` 去重（X 用帖子 ID，YouTube 用视频 ID，网页用规范化后的地址）。便签使用各自的键，不会互相占用。

## API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` / `POST` | `/api/boards` | 列出或新建画板 |
| `PATCH` / `DELETE` | `/api/boards/:id` | 重命名或删除 |
| `GET` / `POST` | `/api/boards/:id/cards` | 列出卡片，或添加链接 / 便签 |
| `PATCH` / `DELETE` | `/api/boards/:id/cards/:cardId` | 改位置或正文，或删除 |
| `POST` | `/api/boards/:id/cards/:cardId/retry` | 重新抓取 |
| `GET` / `POST` | `/api/boards/:id/sessions` | 列出会话或新建会话 |
| `GET` / `POST` | `/api/boards/:id/sessions/:sessionId/messages` | 读取或发送问题 |

重复链接返回 `409`，正文是 `{ "error": "已存在", "card": { ... } }`。其他错误仍然是 `{ "error": "..." }`。

添加链接时卡片先以 `loading` 返回，抓取结束后通过 SSE 的 `board_card` 更新。失败时 `status` 为 `failed`，`error` 为「抓取失败」。
